## Findings

- **[severity: bug]** docker/docker-compose.yml:16-20 (header's second-instance example) and docker/README.md "A second instance" ("Drop `COMPOSE_FILE` to run on the base file's memory") — both start the second project without naming a compose file, so Compose also merges `docker/docker-compose.override.yml` when one exists, and `tuning.md` says smaller hosts keep one there. One such override, kept outside this repo and written to be copied into `docker/`, sets the db's volumes with `!override` to a named volume declared `external: true` with a fixed `name:`, the live database's volume. I checked with `docker compose config` (Compose v2.15.1, scratch copy of the base file plus an override of that shape). With the header's exact variables (`COMPOSE_PROJECT_NAME=fresh-2 … FRESH_DB_DATA=./postgres-data-2`), project `fresh-2`'s db mounts the external volume, not `./postgres-data-2`. With the README's `COMPOSE_FILE` set, it mounts `./postgres-data-2`. So on that host the header example, or the README recipe with `COMPOSE_FILE` dropped as it suggests, starts a second container on the live database's data directory, on the trixie image (that override sets no `image:`), beside the running live server. Separately, the Image section offers `image:` in the override as a way to pin a host to bullseye. A literal `image:` there outranks an exported `FRESH_DB_IMAGE` (also checked: `config --images db` gave bullseye), so the header's claim that a second instance "exports FRESH_DB_IMAGE" to get the new image fails on such a host. `run.sh` avoids both problems because it passes `-f` for both files; the two documented recipes do not. Fix: name the base file in every second-instance command. In the header example use `docker compose -f docker-compose.yml up -d db` (or `COMPOSE_FILE=docker-compose.yml`). In the README, replace "drop `COMPOSE_FILE`" with "set `COMPOSE_FILE=docker-compose.yml`", and say why: a host override names the first instance's volume and image.
  - **Rule:** code-check.md "A fix lands in one of two callers that share a harness" ; code-check.md "A guard's scope, escape hatches, and remedies"
