## Findings

- **[severity: fragile]** tests/testthat/helper-test_names.R:192-196 (`.frs_test_guard_files()` excludes `helper-db.R`), combined with lines 116-136 (the live-connector fixpoint is built only from definitions in the scanned files). `local_fwapg_indexpoint()` is defined in helper-db.R. It opens a connection (through `local_fwapg()`), but it is neither in `.frs_test_live_base` nor in any scanned file, so the fixpoint never learns it is a connector. A `test_that()` block whose only connection is `conn <- local_fwapg_indexpoint()` is therefore classed as not live and skipped whole. Probe: a snippet block with that connection and `DBI::dbExecute(conn, "CREATE TABLE working.test_gate_x (a int)")` gives **0 hits**. The same snippet scanned together with helper-db.R flags it. No current test does this; test-frs_fwapg_gate.R uses the helper and writes no table, so the tree is clean today. But the guard's stated scope ("or to any top-level function in the scanned files that itself calls one"; CLAUDE.md: "scans every test, helper and setup file") is wider than what it checks. The gap is silent, and it sits on the local-fwapg connection, where two runs against one docker DB do collide. Fix: add `local_fwapg_indexpoint` to `.frs_test_live_base`, or seed the fixpoint from helper-db.R's definitions while still not scanning that file's strings. Then pin it with a snippet test like the `my_conn` one.
